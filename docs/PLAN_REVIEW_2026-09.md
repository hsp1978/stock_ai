# 외부 개선계획서 타당성 검토 (2026-09-11)

> **대상**: "Stock AI Multi-Agent Analysis System v2.0 — 개선 계획서" (사후검증 8건 기반)
> **검토 방법**: 계획서의 17개 패치 제안을 현재 `main` 코드와 1:1 대조.
> 계획서는 "코드베이스 구조를 모르는 상태에서 작성"됐다고 명시하므로, 진단의 전제부터 확인했다.
> **결론**: 3건 적용, 5건 이미 구현, 2건 근거 스테일(보류), 7건 유효하나 미적용, 1건 기존 코드와 충돌.

계획서가 인용한 리포트는 2026-04~08 산출물이고, 그 뒤 #16~#37에서 같은 결함들이 수정됐다.

| 계획서 항목 | 실제 상태 |
|---|---|

## 2. 근거가 스테일해 보류한 항목

### P1-1 V1 집계 로직 교체 — **보류 권고**

계획서 진단: "정상 작동 5건 전부 HOLD, composite +0.24~+1.24에 몰림, 판별력 0".

**전제가 이미 무효다.** 그 5건은 신호 임계가 `±2.0`이던 시점의 산출물이고, `±2.0`은 도구
**합계** 스케일 잔재로 평균 스케일에서는 도달 불가였다(2026-07-30 진단, #16에서 `1.3 / -0.5`로
재정합). 즉 "전부 HOLD"의 원인은 집계 산식이 아니라 **도달 불가 임계**였고 이미 고쳐졌다.

재정합 후 실측(최근 60일 `scan_log`):

| 신호 | 건수 | 비율 |
|---|---:|---:|
| BUY | 2,091 | 7.9% |
| HOLD | 22,569 | 85.7% |
| SELL | 1,705 | 6.5% |

계획서의 `composite = directional * (1 + |asymmetry|)` 배수를 **재정합된 임계 위에 그대로 얹으면
이중 보정**이 된다(임계는 이미 현 분포에 맞춰 내려가 있다). 적용 전 반드시:

1. 현 임계 기준으로 골든셋 9건을 재실행해 baseline을 다시 산출할 것 (계획서의 `hold_ratio 100%`,
   `direction_accuracy 4/7`은 구 임계 산출물이다)
2. 임계 튜닝은 9건이 아니라 **이미 확보된 평가 표본(4,272건 / 독립 블록 378개, §SYSTEM_OVERVIEW 11)**
   으로 할 것. 9건 튜닝은 계획서 §8.5가 스스로 경고한 과적합이다.

단, **"매도 0개"라는 비대칭 정보를 별도 필드로 드러내는 것**(현재는 평균에 흡수)은 산식 변경 없이도
가능하고 가치 있다 — 별건으로 권고.

### §8 목표 지표 — 재산출 필요

`baseline: direction_accuracy 4/7, hold_ratio 100%`는 구 임계·구 로직 기준이다.
현 코드로 골든셋을 재실행하지 않은 상태에서 이 목표치를 KPI로 쓰면 방향이 왜곡된다.

## 3. 이번에 적용한 항목 (커밋 `0c21db9`)

코드에 **실제로 부재함을 확인한 부분만** 반영했다.

| 항목 | 적용 내용 |
|---|---|
| **P1-3** 펀더멘털 게이트 | `_check_fundamental_risks`는 P/E·Beta 경고를 이미 만들고 있었으나 **신호를 막지 못했다**. `_apply_valuation_gate()` 추가 — critical risk 있으면 매수 → 관망, 신뢰도 3.0 상한, `execution_ready=False`, 사유를 risks/conflicts에 노출. 적자+EBITDA 마진 <−10% 조합을 critical risk로 추가(SKAI). 순현금 > 시총 80%면 deep value 근거를 warnings에 남김(삼영무역) — **점수는 변경하지 않음**. 펀더멘털 데이터 부재 시 `"특별한 리스크 없음"` 대신 `"데이터 부재 — 리스크 평가 불완전"`. |
| **P1-5** Beta 연동 손절 | Beta > 1.5면 손절폭을 `min(beta, 2.0)`배 확대하고 R/R 설계를 유지하기 위해 익절도 같은 비율로 확대. 수량을 `1/scale`로 줄여야 함을 notes에 명시(주당 리스크 증가). |
| **P1-4** 출구 규칙 | `build_requests_from_entry_plan`이 `stop_loss=None`인 계획도 주문으로 변환했다 → 거부 + 사유 로깅. 계획서의 "buy 신호 자체를 neutral 강등"은 채택하지 않음 — 이미 `execution_ready=False`가 붙고, 신호 강등은 판정 의미를 흐린다. |

검증: 신규 테스트 8건 + 전체 565 tests 통과, ruff clean, 재빌드·배포 후 `/health` 정상.

## 5. 기존 코드와 충돌 — 결정 필요

### §7 금지2 "52주 고점 초과 진입가 실격 처리 금지" vs `entry_plan.py:249`

현재 코드는 진입가가 52주 고점을 넘으면 `order_type="wait"` / `entry_timing="wait"`로 **진입을
보류**한다. 계획서는 이를 금지하고 "경고만 남기고 통과"를 요구한다(SKAI가 고점 ₩3,480 위
₩4,000 진입가에서 ₩6,160까지 갔다는 근거).

**양측 근거가 갈린다.** SKAI는 고점 돌파 후 +54%까지 갔지만 현재는 ₩2,400대로 진입가 대비
−40%다. 출구 규칙이 있으면 통과가 옳고, 없으면 보류가 옳다 — 결정적 변수는 P1-4(출구 규칙)이며
이번 커밋으로 손절 없는 주문은 차단된다.

현 구현은 "신호 실격"이 아니라 "진입 타이밍 보류"이므로 계획서가 금지한 형태와 정확히 같지는
않다. **변경하지 않았다** — 단일 사례로 보수적 안전장치를 제거할 근거가 부족하다. 완화하려면
"출구 규칙이 완비된 경우에만 돌파 진입 허용" 형태가 맞다.
